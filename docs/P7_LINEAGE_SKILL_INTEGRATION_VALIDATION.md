기준일: **2026-11-05**, 프로젝트: `C:\dev\UMA`.

기존7인·31인 계보의 소유 노드에 백인자 기록과 제작 목표를 연결하고, 사용자가 명시한 노드별 우선순위로 P6 추천을 계산한다. 실제 P3/P5 자료와 기존 인물 ID를 사용한 **부모·조부·최종 대상3종 통합 계산**은 통과했다. 아래 백인자 목록은 **사용자가 입력하는 상황을 만든 테스트 기록**이며, 한국 서버에서 관측한 실물 완성 인자나 게임 내 획득 성공 사례가 아니다.

**전체 단위493개·PC/모바일62개 회귀와 실제 DB 통합 검증을 통과했다.** P7 기능의 수용 검증과 백인자 자격·한국 게임 정확도의 미인증 상태를 구분한다.

## 2. 백인자 확장 구조와 보유·계획 구분

`src/domain/lineage-skills.ts`의 `LineageSkillState`는 P2 계획·게임 DB와 분리한 **세션 내 사용자 정보 계층**이다. 새로고침 후 저장·복구나 서버 DB를 구현한 것이 아니다.

| 계층 | 기록 내용 | 의미 |
|---|---|---|
| 노드 인자 목록 | nodeId·ownerCostumeId·목록 확인 상태·records | 실제 인자 소유 노드에 바인딩 |
| 백인자 레코드 | canonical skillId·한국어/일본어명·별수1～3 또는null | 이름 유사성으로 다른 ID를 합치지 않음 |
| 레코드 상태 | `owned` / `planned` | 사용자 실제 보유 기록 / 아직 확보하지 않은 제작 목표 |
| 입력·분류 | `userEntered:true`·classification·근거 문자열 | 사용자 진술과 데이터 자격 검증의 구분 |
| 노드별 목표 | ownerCostumeId·P6 우선순위 목록 | 해당 소유 노드에만 적용되는 명시적 추천 입력 |

목록 상태는 `unentered`(미입력), `partial`(일부 입력), `reviewed`(사용자가 전체 목록을 확인)다. 미입력·부분 입력을 미보유로 판정하지 않는다. 전체 목록을 확인했다고 명시한 노드에서만 기록 밖의 목표를 사용자 확인 기준의 없음으로 표시한다. 실제 보유 기록이 있으면 미입력 상태로 되돌릴 수 없고, 실제 보유 추가는 부분 입력으로 전환한다. 캐릭터 미정 노드는 제작 목표만 기록할 수 있다.

별수는 기록값이며 성공률로 환산하지 않는다. 같은 스킬의 실제 보유와 제작 목표를 별도 상태로 동시에 기록할 수 있다. 기록을 바꾸는 것만으로 P6 우선순위가 자동 생성되지 않는다.

**백인자 자격 인증은 현재0건이다.** 기존 자료에서 일반 백인자 대상 자격을 직접 검증할 표를 확인하지 못했으므로, 일반 희귀도·이름·습득 경로만으로 정상 자격으로 올리지 않는다. 연결 가능한 일반 스킬도 `review-required`로 남긴다. 금색·◎ 검색은 P6의 명시적인 일반 하위 관계만 사용하며, 실제 계승 고유900011 등 고유·진화·계승 전용은 일반 목표로 변환하지 않는다. 원자료의 `gene_version`을 일반 백인자 증거로 오해하지 않았다.

같은 캐릭터를 배치한 서로 다른 nodeId의 목록을 분리했다. 의상 소유자가 바뀌면 이전 목록과 그 노드의 목표를 제거하며, 계보 비우기도 사용자 계보 정보 초기화로 처리한다. 조부 재배치처럼 nodeId와 소유자가 유지되는 연결 변경에서는 기록을 보존한다. 잠금된 노드의 기록은 UI에서 **잠금된 인자의 백인자 기록 편집**을 명시한 경우에만 편집하며, 이 편집은 P2 캐릭터·적인자·잠금·연결을 바꾸지 않는다.

## 3. 노드별 조상과 스킬 분석

분석은 선택 노드의 실제 부모2명, 그 부모들의 실제 부모4명을 따라간다. 원래7인 화면의 고정 슬롯 이름을 모든 육성 단계의 부모로 재사용하지 않는다.

## 4. P6 사용자 우선순위 연결

계보 상세의 **이 노드의 인자작 우선순위**는 기존 P6 검색·canonical ID·우선/강력/필수 UI를 재사용한다. 전역 추천과 노드 추천은 별도 범위다. 다른 노드를 선택하거나 전역으로 전환하면 이전 노드의 숨은 필수 조건을 가져오지 않으며, 각각의 입력은 세션 내 보존한다.

- 우선 확보+8·강력 우대+24는 기존 사용자 정책값, 필수 확보는 가산0의 같은6장·양립 이벤트 계획 수급 조건이다.
- 노드마다 최대5개다. 제한을 넘는 요청은 거부하며 기존 목표나 필수 조건을 조용히 삭제하지 않는다.
- 전역 목표는 읽기 전용으로 별도 표시하고 현재 노드에 자동 병합하지 않는다. 엔진 helper의 명시적 병합도5개 제한·canonical 중복·필수 우선순위를 검증한다.
- 실제 보유·제작 계획·본육성 수급 경로가 있어도 사용자 목표를 자동 해제하지 않는다. 백인자 정보만 입력한 상태와 아무 정보가 없는 상태는 같은 P6 계산 요청을 만든다.

계보의 노드 버튼에서 **선택한 인자의 서포트 추천**을 눌러 해당 노드의 계산 범위를 적용한다. 노드 추천은 필요한 때 선택 노드 하나만 계산한다. 목표·노드·대회·가용성·혈통이 바뀌면 오래된 결과를 무효화하고, 다른 노드의 Worker 응답을 현재 결과로 표시하지 않는다.31개 노드를 동시에 최적화하지 않는다.

## 7. 최종 본육성과 두 종류의 서포트 수급

최종 대상은 `target`의 **다이와 스칼렛 [톱・오브・블루]**, 인물1009·의상100901이다. 부모 parentA·parentB 및 조부4명만 직접 두 세대의 백인자 검토 근거로 사용한다. target 자체에는 실제 보유 기록을 넣지 않았다.

| 대상 단계 | 계산에 전달하는 본육성 덱 | 표시·해석 |

| 최종 본육성 target | 입력한 최종 본육성6장 | 최종 대상의 직접 잠재 수급 경로 |

노드별 인자작 추천6장은 이 최종 덱과 독립적으로 탐색한다. 결과에서 **최종 본육성 잠재 경로**와 **선택 인자작 양립 경로**를 구분하고, 같은 목표를 공급하는 카드·일반 힌트·이벤트·금색 하위 유형과 차이를 보여준다. 본육성의 잠재 경로 목록을 이벤트가 모두 양립하는 확정 획득 목록으로 해석하지 않는다.

## 9. 현재 인자작과 명시적 미래시의 차이

P7 노드별 인자작의 기본 모드는 **현재 한국 수급**이다. 미래 대회가 선택돼 있어도 기본 인자작 요청은 현재 날짜·`allowForecast:false`·일본 대회 컨텍스트 없음으로 만든다. 대회 시점의 최종 본육성 수급을 부모·조부의 현재 수급과 혼용하지 않는다.

미래시 설계를 직접 선택한 경우에만 P5의 **일본 출시일↔대응 일본 대회일** 순서 판정을 사용한다. 한국 예상 날짜로 순서를 뒤집지 않는다. 알려진 대회 후 출시 콘텐츠를 해당 대회에 넣지 않으며, 선택 시나리오 가용성을 확인하지 못하면 계산 사유를 표시한다.

실제 DB 차이 검증은 parentB에 **우등생203842 필수**를 지정하고 CM40 환경에서 수행했다.

| 모드 | 결과 | 근거 |
|---|---|---|
| 현재 한국 기준 | `required-unfulfilled` / `unverified-source`, 맞춤6장 없음 | 현재 한국 카드의 일본 전용 원문을 한국 검증 수급으로 승격하지 않음 |
| 명시적 미래시 설계 | 기본378+선호0=378, 목표50·녹딱5 | 미래 카드10133의 JP 원본 경로를 대응 일본 대회 전 수급 예상으로 사용 |

미래시6장은 **30037·10132·30102·30234·30173·10133**이다. 어드마이어 그루브10133은 현재 한국 모드에서는 가용 카드가 아니며, 미래시에서는 원래 JP 출처와 예상 상태를 보존한다. 이를 실제 한국 보유 카드나 현재 획득 가능으로 표시하지 않는다.

미래시로 전환해도 과거 사용자가 기록한 `owned`와 앞으로 만들 `planned`를 자동 변환하지 않는다. 가용성·우선순위·보유 제한·이벤트 양립성은 새 요청에서 다시 검사한다.

## 10. 중복 힌트·이벤트 경로와 기존 정책

계보의 중복 보유 위치, 최종 본육성의 잠재 수급 경로, 선택 인자작 계획의 실제 호환 경로를 다른 정보로 유지한다. 카드별 원본 힌트·이벤트·금색 하위 경로와 sourceServer를 보존하고, 선택한 이벤트의 모든 관련 그룹이 그 원스킬을 허용하는지 AND로 대조했다. `source_unspecified` 자료는 새 한국 공급으로 추가하지 않는다.

인자작의 중복 공급은 카드 수와 일반 힌트/이벤트/금색 하위 종류를 표시한다. 중복 경로가 많거나 적다는 사실을 새로운 획득 안정성 점수·감점·성공률로 바꾸지 않았다. P6.1에서 비교한 A/B 모두382점, 우선 녹딱4개였고 공급 중복 발생7/4로 B가 앞서는 기존 정책을 유지한다.

운영 추천 엔진 SHA-256은 P6.1과 동일한 `c659d0608aa863e3ee788592fe0371a74e70a9ba49315ecc2518474b85ad2382`다. 백인자 보유 여부가 이 기본 가중치·동률 순서·후보 공급자 확장·필수 조건을 변경하지 않는다. 한도가 있는 탐색 결과를 전체DB의 전역 최적으로 표시하지 않는다.

## 12. 남은 데이터 공백과 후속 개발

백인자 대상 자격을 직접 인증할 원본 표가 없어 현재 분류 완료는0건이다. 일부 스킬 효과·조건, 한국 과거 패치·최초 출시일, 이벤트 서버·선택 조건·발생/성공률·획득 보장, 미래 한국 출시·대회 일정의 공식 확인 공백도 유지한다. 일반 스킬 ID나 실제 수급 경로가 있다는 사실만으로 이 공백을 메우지 않았다.

계보 정보·목표·화면 간 입력은 같은 세션에서 유지한다. P8의 저장/불러오기·새로고침 후 영구 복구를 앞당겨 구현하지 않았다. 로그인·서버DB·이미지 출력·정적 배포·종마 자동 교체·전체31인 자동 생성·백인자 생성/계승 확률·마신 시너지·육성 시뮬레이션·G1 가산은 추가하지 않았다.

후속 데이터 검증에서는 백인자 자격의 ID별 명시 근거, 이벤트 조건과 서버 패치, 실제 수급 안정성의 독립 자료를 먼저 보완해야 한다. 그런 자료가 확보되기 전에는 소유 기록·제작 목표·서포트 수급 기회를 서로 다른 정보로 유지하고 기존 추천 정책을 바꾸지 않는다.
