5. 공개식 회귀·실자료 계획 검증과 한국 게임 실측 인증을 구별한다. 세부 결과는 [P2_LINEAGE_VERIFICATION.md](P2_LINEAGE_VERIFICATION.md)를 따른다.

## P1 결정 · 2026-11-05

준비 자료가 들어온 뒤의 추가 결정은 `DATA_INTEGRATION.md`를 따른다. P0와 아래 가상 회귀 계약을 유지하고 별도 P1 참고 계약을 추가했다. 미확인 KR 출시·일본 그룹 자료·계산 검증 대기를 보존하며, 별도 로컬 스냅샷은 개발 서버에서만 제공한다.

1. P0 스냅샷·엔진·검증 화면을 보존한다. 초기 화면을 7인 계보로 변경하고, P0 검증 화면은 `?view=data`와 헤더 버튼으로 접근한다. 화면 간 이동 중 계보 입력은 메모리에 유지한다.
2. 실제 데이터가 없어 P1 전용 가상 스냅샷과 별도 규칙 팩을 만든다. P0의 스키마 v1은 변경하지 않는다. 규칙 팩은 `snapshotId`와 출처·fixture 상태를 일치시켜 검증하고 재귀 동결한다.
3. 상성은 명시된 관계 항목과 가중치로 계산한다. P1 fixture의 11관계 합산식·동일 인물 제한은 실게임에서 검증한 공식이 아니다. 실제 식과 불일치하면 규칙 모델·엔진 수정이 필요하다. 데이터 교체만으로 검증 완료라고 표시하지 않는다.
4. 필수 상성쌍이 없으면 `unavailable`, 미선택 슬롯은 `partial`, 금지 인물 조합·잘못된 ID는 `invalid`다. 완성되고 모든 데이터가 있을 때만 `total`을 제공한다. 부분합은 별도 표기하며 누락을 0으로 대체하지 않는다.
5. 후보는 기존 `projectAvailability`를 재사용해 한국 출시 기준으로 제한한다. 정식명/일본어명/별명/의상명을 NFKC 정규화해 검색한다. 상성 평가 상태·비교값·이름·ID로 안정적으로 정렬한다.
6. 날짜를 변경해 선택 개체가 가용 범위에서 벗어나도 원래 선택은 유지한다. 계산용 사본에서 해당 슬롯의 의상과 인자를 함께 제외하고 화면에 알린다. 후보 계산도 같은 사본을 사용한다.
7. 6배치는 부모·대상을 고정하고 조부 4슬롯 중 부모 A에 둘을 선택한다. 같은 부모 아래 형제 슬롯 교환이 점수·제한에 영향을 주지 않도록 규칙을 검증한다. 인자는 조부와 함께 이동한다. 결과는 제안이며 버튼으로 새 계보 설계에 적용한다. 실제 보유 완성 혈통의 가져오기/자동 변경은 없다.
8. 적성은 본육성 대상의 의상별 초기값에 실제 선택된 부모 2/조부 4 인자의 별수를 적용한다. 대상 자신과 미선택 슬롯에 남은 인자는 제외한다. 별수표와 A 상한은 현재 가상 규칙이며 기존 S는 내려가지 않는다.
9. 데이터 부족 상태에서 계승 고유를 만들어 내지 않는다. PED-04의 상성순 추천은 구현하되 계승 고유 확인·선택 반영은 별도 미구현으로 기록한다. 이번 사용자 지정 범위인 다섯 기능 이외로 확장하지 않는다.
