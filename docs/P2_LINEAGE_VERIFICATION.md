# P1 마무리와 P2 31인 계보 설계

확인일: 2026-11-05 · 프로젝트: `C:\dev\UMA`

## 구현 범위

P0 계약과 fixture를 유지했다. P1의 GameTora 159점 대조 계산식과 공개 초기 적성 엔진도 유지하고, 실제 계보 UI에서 기본 활성화했다. 개발 서버는 로컬 자료가 있으면 실제 자료 계보를 먼저 연다. 자료가 없으면 가상 화면으로 전환하며 출처를 구분한다. `?view=fixture`는 기존 가상 회귀 화면, `?view=data`는 P0 진단 화면이다.

P2는 기본 7인을 유지하면서 `상세 31인 보기`에서 증조 8명·고조 16명의 계획을 펼친다. 혈통별 접기, 캐릭터/의상 검색, 빨간 인자 종류·1～3성, 보유 혈통 고정, 로테이션 설계 프로필, 선택적 유전자 목표, 자동 배분 전후 비교와 명시 적용을 제공한다.

## 인자 소유와 혈통 연결

`LineagePlan`은 31개 고유 `nodeId`와 `parentIds`로 구성한다. 동일 캐릭터를 여러 번 배치해도 각 인자 소유 노드는 별도다. 상성 배치가 바뀌면 부모의 조부모 연결만 재연결하며 조부의 캐릭터·인자·증조/고조 혈통은 함께 이동한다. 같은 의상과 인자라도 깊은 혈통이 다른 소유자를 임의로 합치지 않는다.

검증기는 세대별 1/2/4/8/16개, 존재하는 부모 참조, 단일 소유 노드, 순환·공유·분리 노드, 깊이 범위를 검사한다. `locked` 노드와 그보다 오래된 혈통은 수동 수정·자동 배분·부모 혈통 재배치로 바꾸지 못한다. 원본 JSON을 직접 넣어도 고정 혈통에 캐릭터가 미정인 인자를 실제 보유 인자로 통과시키지 않는다.

새로 만들 인자는 캐릭터 미정 상태에서도 별수 계획을 세울 수 있다. 이는 확보된 완성 인자로 추천한다는 뜻이 아니다. 캐릭터를 임의 생성하지 않으며 실제 보유 인자로 고정하려면 해당 인자 소유 캐릭터를 선택해야 한다.

## 세대별 효과와 제약

각 육성 노드의 직접 부모 2명과 조부모 4명만 시작 적성에 반영한다. 기존 공개 보정식을 공용 helper로 추출했으며 수식은 바꾸지 않았다.

| 본육성에서의 세대 | 조부모 육성 | 부모 육성 | 본육성 |
|---|---|---|---|
| 부모(depth 1) | 해당 없음 | 자신의 인자를 자신에게 적용하지 않음 | 반영 |
| 조부(depth 2) | 자신의 인자를 자신에게 적용하지 않음 | 반영 | 반영 |
| 증조(depth 3) | 반영 | 반영 | 직접 반영하지 않음 |
| 고조(depth 4) | 반영 | 직접 반영하지 않음 | 직접 반영하지 않음 |

- 조부의 목표 빨간 인자는 기본 7인에서 선택한 종류를 그대로 사용해 생성 목표 A를 검사한다.
- 부모에 선택된 빨간 인자의 생성 목표 A도 유지해 증조 배분이 부모의 필수 조건을 해치지 않게 한다.
- 로테이션은 선택형 설계 프로필과 사용자 목표 등급(D/C/B/A)으로 관리한다. 모든 캐릭터의 더트·마일 기준을 하나의 상수로 고정하지 않는다. 이 등급은 사용자가 정하는 계획 기준이며 완주율 예측이 아니다.
- 시작 적성 보정은 공개 표의 최대 4단계·A 상한을 따른다. 예를 들어 G→A는 이 시작 보정만으로 불가능하다고 설명한다. 육성 중 이벤트로 오를 확률이나 최종 적성을 시뮬레이션하지 않는다.

## 자동 배분 순서

1. 고정 인자·혈통과 목표 A·로테이션·부모 생성 조건을 충족한다.
2. 다른 필수 조건에 손실 없이 가능하면 유전자 12성 목표를 택한다.
3. 12성이 충돌하면 6성 대안을 탐색한다. 6성도 불가능하면 사유를 표시한다.
4. 같은 충족 조건·총별수에서는 같은 종류 인자를 한쪽 가지에 집중한다. 집중은 혈통 재사용 편의이며 획득 확률 증가로 표현하지 않는다.

조부별 증조 2+고조 4의 6슬롯 별수 배치를 탐색한 뒤, 증조 인자가 함께 영향을 주는 부모 조건을 결합한다. 캐릭터·소유 ID·연결은 바꾸지 않고 depth 3/4의 조정 가능한 인자만 변경한다. 고정된 인자는 그대로 둔다. 인물 선택이 고정된 배분에서는 기본 상성도 변하지 않는다.

탐색 기본 상한은 1,000,000상태다. 한도를 넘으면 `search-limited`로 보고하고 불가능으로 판정하거나 부분 결과를 적용하지 않는다. 결과에는 확인한 상태 수와 전후 평가를 남긴다.

선택된 31노드 전체에 한국 출시 기준을 적용한다. 기준일 이후·미확인 제외 선택은 보존하면서 P2 계산/배분을 차단한다. 캐릭터 미정의 신규 계획 슬롯과 혼동하지 않는다. 입력 조건이나 날짜가 바뀐 뒤에는 오래된 배분안을 적용할 수 없다.

## 실제 계산 검증

기존 외부 기대값을 새로 생성하지 않고 그대로 재사용했다. [P1 검증 보고서](P1_CALCULATION_VERIFICATION.md)의 GameTora 일치 사례다.

- 7개 기여: **31 / 26 / 24 / 22 / 23 / 15 / 18**
- 합계: **159**. 기본 UI에서 추가 모드 없이 일치
- 같은 조부 4명의 로컬 6배치: **164 / 161 / 159 / 157 / 155 / 152**. 외부에서 6개 전부를 실측한 값은 아니며 기존 전순열 oracle과 재연결 회귀로 확인
- 실제 데이터의 조부 4명에게 마일 A 생성·잔디 A·더트 유전자 목표를 부여한 31인 설계: 필수 조건 모두 충족, 유전자 **12/12/12/6성**, 인자 변경 **19개**, 소유·연결 변경 **0개**, 확인 상태 **12,391개**
- 테이오의 기본 마일 E를 A로 올리는 데 필요한 조건 때문에 해당 가지는 6성 대안을 선택. 기존 공개 초기 적성 경계 기대값을 재사용한 계획 계산이며 실제 인자 획득 인증은 아님
- 실제 전체 로컬 자료를 PC 1440px/모바일 375px에서 실행해 159점·7개 기여·24개 추가 슬롯·전후 비교·6성 대안·재배치와 JS 오류 0건 확인

검증 보고서: `data/local/p1-calculation.validation.json`, `data/local/p2-lineage.validation.json`.

```powershell

npm.cmd run test:e2e
npx.cmd tsx scripts/validate/reference-calculation.ts

```

최종 회귀: 단위 **295개 / 20파일**, PC·모바일 브라우저 **28개**. 그래프 무결성, 고정 혈통, 세대 범위, 12→6 대안, 부모 교차 제약, 같은 별수의 집중, 탐색 한도, 오래된 미리보기, 깊은 노드의 출시 제외를 포함한다.

## 근거와 남은 공백

- 부모/조부의 시작 보너스와 육성 중 계승은 [GameTora 계승 설명](https://gametora.com/umamusume/legacies)의 구분을 따른다. 공개 적성 표와 외부 159점은 기존 P1 보고서에 원문과 기대값을 보존했다.
- 6성 유전자 구성은 [やまねこ의 2025-03-04 설계 기록](https://note.com/ymneko_rta/n/n15de25cadf48)에서 부모·조부 6명의 별수 구조를 확인했다. 12성 관련 공개 설명은 [GameWith 인자 루프](https://gamewith.jp/uma-musume/article/show/260515)를 추가 참고했다. 이들은 한국 공식 사양이나 한국 서버 실측으로 승격하지 않는다.
- 유전자 6/12는 사용자 확정 설계 목표로 평가하며 획득 확률을 점수에 곱하지 않는다. 한국 서버의 실제 유전자 획득 사례와 패치 적용 확인은 추가 검증이 필요하다.
- 한국 서버 자체 실측은 여전히 **0건**이다. 계산은 공개식/공개 표 근거로 사용 가능하게 두고 이 상태를 출처에 표시한다.
- 선택형 로테이션은 적성 기준 프로필이다. 특정 시나리오의 전체 레이스 일정과 승률·완주율 예측은 추가하지 않았다.
- 캐릭터 미정의 계획 인자 실물 확보, 게임 이미지 권리, 한국 명칭/출시 전수 검수는 남아 있다. 저장·PNG 내보내기는 기존 후속 단계다.

다음 개발 단계는 기존 계획의 P3(대회별 스킬 평가·본육성 덱 데이터)다. P2 추가 실측은 위 기록과 골든테스트에 누적한다. G1 우승 가산·정밀 육성 시뮬레이션·서포트 추천은 이번 작업에 추가하지 않았다.
