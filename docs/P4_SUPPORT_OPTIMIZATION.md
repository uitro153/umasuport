## 사용과 구현 범위

`npm.cmd run dev` 후 **스킬·서포트 분석**의 **인자작 서포트 6장 추천**에서 계산한다. 기존 대회·각질·시나리오·성향·본육성 6장을 재사용하며, 본육성 편성을 입력하지 않아도 추천할 수 있다. 보유 등록은 선택 사항이다. 미등록 카드는 전체 가용 DB의 4돌파 가상 설계로 비교한다. 보유 제한을 켜면 등록 돌파를 유지하고 미보유 카드 대여를 최대 1장으로 제한한다.

P0～P3 계약과 계산을 유지했다. 기존 JSON·SQLite와 P3 평가·수급 분석을 재사용하며 새 추천 DB를 만들거나 같은 원자료를 재수집하지 않았다. P4 계산은 `src/engine/support-deck-optimizer.ts`의 순수 함수이고 Worker에서 실행한다. 데이터는 Worker 초기화 때 한 번 전달하고 다음 계산은 요청만 전송한다. 입력이 바뀐 옛 결과는 숨긴다.

결과에는 추천 6장, 카드별 독점 기여·채용 이유, 유효 스킬·녹딱·중복·주요 누락, 일반 힌트·이벤트·금색 하위 경로, 교체 전후 얻고 잃는 스킬, 실제 스킬 구성이 다른 대체 편성을 표시한다. 대체 편성은 최대 1개이며 이름만 다른 편성을 억지로 늘리지 않는다. 모바일 카드는 한 열로 읽고 상세 경로를 펼친다.

## 조합 목적함수와 탐색

평가 가능한 일반 백인자 목표의 **서로 다른 스킬 합집합**을 평가한다. 같은 스킬의 힌트·이벤트·금색 하위 경로가 여러 개여도 신규 가치가 반복 가산되지 않는다. 명시적 하위 관계로 이어진 ○·◎ 계열도 같은 목표로 묶는다. 금색 스킬 자체를 별도의 백인자 목표로 더하지 않고 하위 경로를 사용한다. 수급 경로가 없는 경기 전용 히어로 효과·육성 목표 보너스는 빠진 백인자처럼 표시하지 않는다.

P3 정성 등급의 정책 가중치는 우선 확보/유효/조건부/부가에 각각 **16/10/6/2**다. 마신·발동률·백인자화 확률이 아니다. 저비용 스피드·스태미나 녹딱을 우대하며 고비용 자신감 등은 부가 평가를 유지한다. 같은 합집합 가치라면 우선 녹딱 수를 먼저 비교하고 성향별 구성·중복을 비교한다. SR이 과도한 편성의 불이익과 타입 다양성은 동률 선호이며 더 많은 유효 스킬을 덮어버리는 훈련 점수가 아니다. 특정 주자의 기존 가속기 중복 추정으로 감점하지 않는다. 본육성에서 이미 얻는 스킬도 제거하지 않는다.

가용성·보유·실제 경로로 후보를 선별하고, 고득점 카드뿐 아니라 희소·우선 스킬 공급자를 포함한다. 보유 제한에서는 보유/대여 후보를 나누고 서로 다른 인물의 보유 슬롯을 보존한다. 같은 인물의 다른 버전을 중복 편성하지 않는다. 소유 인물 ID가 없는 입력은 임의로 같은 인물로 합치지 않는다.

- 기본 후보 상한 **96장**, beam **80**, 탐색 한도 **100,000상태**
- 작은 후보군 18장 이하는 예산 내에서 전수 조합 탐색
- 큰 후보군은 여러 완성 시드·beam 조합 탐색 후 최대 4라운드의 한 장 교체 개선
- 실제 스킬 집합과 카드 2장 이상이 다른 경우만 대체 편성 제공
- 후보 수·선별 여부·beam 축소·확인 상태·완성 조합 수·한도 도달·최적성 범위를 결과에 기록

단순 카드 점수 상위 6장을 전역 최적이라고 주장하지 않는다. 범위를 줄인 탐색은 **탐색한 범위의 최선 발견안**이다. 전수 최적성도 요청의 가용·보유 제약을 통과한 후보 집합에 대한 주장이다. 한도로 완성하지 못한 경우, 카드 부족, 평가 가능한 스킬 부족을 구분하며 빈 6장을 정상 추천하지 않는다.
