# 화면·레이아웃·캐릭터 이미지 설계 제안 v1.0

**목표:** 복잡한 기능은 내부에 숨기고, 화면에는 '계보를 편집하고 결과를 보는 데 필요한 것'만 표시한다. 사용자 요청대로 조밀하고 직관적인 일본 설계도 방식을 참고하되 독립 디자인으로 구현한다.

## 1. 디자인 원칙

- **주화면은 계보:** 사이트 첫 화면에서 바로 7인 계보 편집 시작. 별도의 기능 설명 페이지부터 강제하지 않음.
- **정보 계층 2단계:** 기본 카드 = 캐릭터 초상·정식 이름·의상 표시·빨간 인자 핵심. 카드 선택/상세에서 전체 적성·상성 상세.
- **가장 중요한 값은 상단 또는 우측 고정:** 현재 기본 상성 합계, 적성 변경, 자동 배분 조건 만족 여부.
- **입력 공간 최소화:** 대회·각질·시나리오·추천 성향은 select 드롭다운. 라디오 버튼 남용 금지.
- **색상 보조:** 빨간 인자는 붉은 색 요소, 패시브 녹딱은 초록 점/라벨, 적성 변화는 텍스트 등급 표시. 의미를 색상에만 의존하지 않음.
- **장식 최소화:** 실제 게임 스크린샷을 배경으로 사용하거나 화면 전체를 캐릭터 일러스트로 채우지 않음.

## 2. 내비게이션과 화면 분리

1. `계보 설계` (기본 랜딩)
2. `서포트 추천` (독립 기능)
3. `저장한 설계` (기본 로컬 목록, 파일 가져오기)
4. 우측 상단 `데이터 기준` — 선택 대회 시점 / 현재 시점, 확정/미래시 상태 보기

### 데스크톱 계보 기본 7인 화면

```text
┌──────────────────────────────────────────────────────────────────────┐
│ [로고] 계보 설계 | 서포트 추천 | 저장한 설계      [대회 기준 ▼] [저장] │
├──────────────────────────────────────────────────────┬───────────────┤
│                                      기본 상성 [○○] │ 조합 요약     │
│                 ┌────────────┐                       │ 기본 상성     │
│                 │ 목표 캐릭터 │                       │ 적성 보정     │
│                 └────────────┘                       │ 계승 고유     │
│            ┌──────────┐ ┌──────────┐                 │ 추천 후보     │
│            │  부모 A  │ │  부모 B  │                 │              │
│            └──────────┘ └──────────┘                 │ [자동 배치]  │
│         ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐          │ [상세 31인] │
│         │ 조A1 │ │ 조A2 │ │ 조B1 │ │ 조B2 │          │              │
│         └──────┘ └──────┘ └──────┘ └──────┘          │              │
└──────────────────────────────────────────────────────┴───────────────┘
```

**권장 크기:** 최대 콘텐츠 폭 1400px, 왼쪽 계보 70~75%, 오른쪽 요약 25~30%. 캐릭터 카드 높이 80~110px, 초상 48~64px, 이름 1~2줄. 데스크톱에서 7명은 한 화면에 대체로 보이도록.

### 상세 31인 화면

- 버튼 `상세 계보 보기` 클릭 시 **기존 7인은 유지한 채 하단/옆 패널에서 혈통 가지를 확장**.
- 부모 A/B 가지 → 조부 2명씩 → 각 조부의 증조 2명 → 고조 4명.
- 고조 슬롯에는 적성 인자 아이콘과 별 수 우선, 캐릭터 초상은 축소.
- 왼쪽에서 값을 편집하면 오른쪽 `적성 충족`, `유전자 6/12성`, `혈통 집중`이 실시간 표시.
- '31명 한 번에 보기'는 데스크톱 확대/스크롤 보기로만, 모바일 필수 기능 아님.

### 모바일 계보 기본 화면

```text
┌─────────────────────────┐
│ [☰] 계보 설계  [저장]    │
│ 기본 상성 ○○   [상세]   │
├─────────────────────────┤
│     [목표 캐릭터]       │
│                         │
│ [부모 A]      [부모 B]   │
│                         │
│ ┌ 부모 A의 조부 [▼] ─┐  │
│ │ [조A1]    [조A2]   │  │
│ └───────────────────┘  │
│ ┌ 부모 B의 조부 [▼] ─┐  │
│ │ [조B1]    [조B2]   │  │
│ └───────────────────┘  │
│ [상성 후보] [자동 배치] │
└─────────────────────────┘
```

- 31인 세대 정보는 가지별 접기/펼치기; 좌우 무한 스크롤 한 장으로 만들지 않음.
- 요약은 화면 상단 배너, 상세 액션은 하단 고정 작업줄 또는 스크롤 영역.
- 모바일 카드 선택은 검색 가능한 다이얼로그/바텀시트에서 진행.

## 3. 서포트 추천 화면

```text
┌────────────────────────────────────────────────────────────────────┐
│ 대회 [구체 대회 ▼] 각질 [선행 ▼] 인자작 시나리오 [무인도 ▼]          │
│ 추천 성향 [균형 우선 ▼]   기준 시점 [대회 ▼]   [추천 실행]           │
├────────────────────────────────────────────────────────────────────┤
│ 본육성 편성  [카드1] [카드2] [카드3] [카드4] [카드5] [카드6]          │
├────────────────────────────────────────────────┬───────────────────┤
│ 추천 인자작 편성                              │ 목표 스킬 현황    │
│ [지원1] [지원2] [지원3] [지원4] [지원5] [지원6]│ 핵심 가속         │
│ 신규 유효 스킬 / 녹딱 / 희귀 스킬              │ 스피드 녹딱      │
│ 이유 / 포기한 스킬 / 다른 편성 비교           │ 놓친 스킬        │
├────────────────────────────────────────────────┴───────────────────┤
│ [종마로 보완 가능한 스킬 후보]                                    │
└────────────────────────────────────────────────────────────────────┘
```

- 대회 종류(챔미/LoH)만 선택하는 것은 불충분하다. **구체 대회와 코스 조건을 선택**하도록 목록을 구성.
- 6장 카드 슬롯은 이미지 확보 전에도 타입·희귀도·이름 텍스트로 충분히 사용 가능.
- 메인 추천 결과에서 `신규로 추가되는 스킬`과 `이미 본육성에서 수급 가능한 스킬`을 구분.
- 유사한 6장 덱을 3개 억지로 나열하지 않음. 1개 + 교체 대안일 수도 있음.

## 4. 시각 디자인 토큰 (권장 선택)

| 요소 | 권장안 |
|---|---|
| 배경 | #F6F7F4 연한 중성 밝은 색 |
| 패널 | #FFFFFF, 경계 #E1E5E2 |
| 기본 텍스트 | #232D29 |
| 메인 액센트 | #346E5D 절제된 진녹색 |
| 빨간 인자 | #B84A5B(색+별 개수 텍스트 동시 표기) |
| 스태미나 패시브 | 초록색 라벨 + '스태' 텍스트 |
| 폰트 | Pretendard 등 공개 사용 조건 확인된 한국어 웹폰트 또는 시스템 기본 글꼴 |
| 간격 | 4/8/12/16/24px |
| 카드 모서리 | 10~12px, 과도한 그림자 없음 |
| 컬러모드 | 밝은 화면 우선; 다크모드는 차후 선택 |

*선택 근거:* 계보의 빨간 인자와 적성 등급 자체가 강한 색상 정보를 갖기 때문에 배경 장식은 줄여야 한다.

## 5. 육성마 이미지/아이콘 명세

### 필수 요소

- `character_base_id`(인물)와 `costume_id`(육성 버전)를 구분한 이미지 매핑.
- 선택창: 96~128px 기준 정사각형 축소 초상 또는 얼굴 중심 상반신(가로/세로 비율 고정).
- 계보 메인 카드: 48~64px 정사각형 초상, 고조 세대에서는 28~40px 정도로 축소 가능.
- 이름 텍스트는 항상 표시. 얼굴 이미지 단독으로 동일 인물의 다른 의상 식별을 강요하지 않음.
- 이미지 등록 파일명은 화면 표시 이름이 아니라 안정된 ID 기반: `char_<costumeId>.webp`.
- 128·256px 자산 생성(권한 확인된 파일만), 원본 왜곡·스트레칭 금지 (`object-fit: cover`).
- 지연 로딩 및 이미지 크기 예약으로 화면 튐 최소화.

### 이미지 선택 우선순위

1. 의상 버전과 정확히 일치하는 초상 또는 카드 일러스트의 식별 가능한 썸네일(권리 확인된 자료만).
2. 의상별 자료가 없지만 `baseId` 동일한 **일반 인물 대표 초상** 사용 시, 의상 대표 그림으로 오인되지 않도록 표시.
3. 둘 다 없으면 **중립 실루엣 + 정식명** 사용. 다른 캐릭터/의상 이미지의 임의 대체는 금지.

### 자산 출처 후보 (재사용 허락이 확보되었다는 뜻 아님)

- Cygames 공식 캐릭터 포털: https://umamusume.jp/
- 카카오게임즈 한국 브랜드 캐릭터 소개: https://umamusume.kakaogames.com/mejiro/index.html
- GameTora 캐릭터 페이지/초상은 외부 참고 후보. 제3자 리소스가 된다고 사용권이 자동 이전되는 것은 아님.
- 공개 JSON+이미지 포맷 연구: https://github.com/Tsuyuchan-jp/umamusume-data
- 실제 팬 사이트 이미지 출처와 게임 저작권 분리 사례: https://uma-tools.com/credits

**가장 안전한 개발 순서:** ID 매핑 → 플레이스홀더 UI 개발 → 게임 이미지 권리·출처 검토 → 승인된 자산만 배포. 이미지가 확보될 때까지 기능 개발을 멈추지 않음.

## 6. 이미지 및 UI 검수 기준

- 실제 캐릭터명과 초상 이미지가 정확히 일치, 의상/육성 버전도 일치.
- 레어도/서포트 타입/고유 이미지가 캐릭터 초상과 섞이지 않음.
- 사이트의 모든 정보는 이미지가 로드되지 않아도 텍스트로 식별 가능.
- 한국어 정식 명칭의 줄바꿈이 좁은 모바일 화면에서 레이아웃을 깨뜨리지 않음.
- 7인 계보 이미지 저장 시 부자연스러운 잘림이나 브라우저 보안(CORS) 실패 없음.
- 계보/추천 결과 생성에서 원본 사이트의 HTML/CSS/이미지를 통째로 복사하지 않음.
