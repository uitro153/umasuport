# P1 가상 계보 데이터와 계산 규칙

`p1.snapshot.json`과 `p1.rules.json`은 **직접 만든 가상 데이터와 가상 규칙**이다. 실제 한국 서버 상성표·적성 보정·동일 인물 제한을 검증한 자료가 아니다. UI에서도 fixture 표기를 유지한다.

- 기존 `p0.snapshot.json`은 그대로 보존한다. P1 스냅샷은 P0 스키마 v1을 재사용하며, 인물 20명·육성 의상 21개·상성쌍 210개를 포함한다.
- 인물 가의 기본/대체 의상은 서로 다른 `costumeId`와 같은 `baseId`를 가진다. 이름·별명·일본어 검색과 의상 구분을 확인할 수 있다.
- 상성쌍은 순서 없는 인물 쌍 1건이며 자기 자신과의 값도 명시한다. `i === j`는 0, 나머지는 `5 + ((i*13 + j*7 + ((i+j)%4)*5) % 31)`로 생성한 가상 수치다. 여기서 `i <= j`는 인물 배열 순서이며 이 생성식은 실제 게임과 관계없다.
- 일반 인물 17명과 한 대체 의상은 2026년에 출시한 설정이다. 캐릭터 러는 2027-01-20 예상, 머는 2027-03-01 예상, 버는 한국 일정 미상이다. 2026-11-05 현재 의상 18개, 2027-02-10 대회 기준 의상 19개가 포함된다.

## 가상 상성 규칙

`p1.rules.json`은 스냅샷 ID와 출처 ID에 고정된다. 상성은 다음 11개 관계의 가상 값을 가중치 1로 더한다.

1. 대상↔부모 2개
2. 부모 A↔부모 B 1개
3. 대상↔조부모 4개
4. 각 부모↔그 부모 아래 조부모 4개

이는 UI·추천·6배치 탐색의 구조를 검증하기 위한 pair-sum 규칙이다. 실제 게임 상성 계산식으로 주장하지 않는다. 대상과 각 부모, 두 부모 사이에만 같은 인물을 금지하는 가상 제한을 두었다. 조부모 같은 가지의 두 슬롯을 바꿔도 점수와 제한이 같아야 규칙 검증을 통과한다.

## 가상 빨간 인자 규칙

별수 임계점은 0/1/4/7/10/13/16, 등급 증가량은 0/1/2/3/4/5/6, 초기 상승 상한은 A로 설정한다. 각 슬롯 인자는 1～3성이며 대상 자신의 인자와 미선택 슬롯의 잔여 인자는 계산에서 제외한다. 이 표도 검증 전 fixture이며 실제 게임 규칙으로 취급하지 않는다.

## 재생성과 교체

```powershell
npx.cmd tsx scripts/fixtures/create-p1.ts
```

위 명령은 P1 가상 JSON 두 개만 재생성한다. 기존 P0 fixture와 실제 원본은 수정하지 않는다.

실제 자료가 확보되면 회귀 테스트 재현을 위해 fixture는 보존하고, 별도의 검증 스냅샷·규칙 팩을 만들어 `src/data/pedigree-data.ts`의 단일 입력 경계에 연결한다. 실게임 값은 출처·적용 패치·동일 인물/의상 처리 규칙과 U-tools/GameTora 등의 독립 기대 결과를 확인한 뒤 `verified`로 바꾼다. 현재 코드에는 외부 사이트 코드나 이미지가 포함되지 않는다.
