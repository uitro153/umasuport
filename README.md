# 한국 서버 우마무스메 인자 설계 도구

현재 수정 단계는 **P8.7.3**입니다. 상위 7인만 캐릭터를 선택하고 증조·고조 24칸은 모브의 적인자를 수동 설계합니다. 31인 자동 배분 패널과 전용 페이지 확장을 제거했으며, 7인 자동 배치·저장 데이터·다크 테마·빠른 선택 설정은 유지합니다. [변경 내용과 집중 검증](docs/P873_MANUAL_LINEAGE.md)을 참고하세요. 전체 회귀와 외부 배포는 P9 전에 별도로 진행합니다.

한국 서버 기준 계보·인자 설계를 만드는 로컬 개발 프로젝트입니다. **P8.7.1에서 동일 캐릭터 부모 제한, 31인 작업 공간 확장, 스킬 목표10개, 빈 빠른 선택 초기값, 라이트·다크 테마와 공통 Footer를 적용했습니다.** 공개 상성은 GameTora 7항목·159점과 대조했고, 스킬·편성은 실제 자료와 정성 평가를 사용합니다. 현재 변경·제한된 검증 범위는 [P8.7.1 수정 결과](docs/P871_CHANGES.md), 이전 전체 회귀 기록은 [P8.7 보고서](docs/P87_USER_FLOW_VALIDATION.md)를 따릅니다.

개발 서버는 준비된 실제 로컬 자료를 기본으로 엽니다. 일본 원자료·출처 번역·한국 출시 미확인·가상 fixture를 구분합니다. 자료가 없으면 가상 화면으로 전환하며, 구조 테스트 통과를 한국 게임 정확도 인증으로 표시하지 않습니다.

## 실행

Node.js 24와 npm을 사용합니다. 이 Windows 환경은 PowerShell의 `npm.ps1` 실행이 제한되어 있어 `npm.cmd`를 사용합니다. 시스템 실행 정책을 바꿀 필요는 없습니다.

```powershell
cd C:\dev\UMA
npm.cmd ci
npm.cmd run dev
```

터미널에 표시되는 로컬 주소(기본 `http://127.0.0.1:5173`)를 엽니다. 첫 화면은 7인 계보이며 카드를 누르면 해당 캐릭터·의상 갤러리가 바로 열립니다. **캐릭터명·의상명·별칭으로 검색하며 DB ID로는 검색하지 않습니다.** 카드와 스킬도 실제 이름으로만 찾습니다. 적인자 배지를 누르면 별도로 종류·별수·고정을 변경합니다. 상성과 10종 시작 적성은 계보 위에서 확인하며, 점수 구성과 보정 과정은 펼쳐 볼 수 있습니다.

부모·조부모의 빨간 인자 종류와 1～3성을 변경하면 실제 원초기 적성에 공개 보정식을 적용합니다. 7명을 모두 선택하면 조부모 최대 6가지 배치를 비교·적용할 수 있습니다. 후보는 한국 출시 시점 필터와 기본 상성으로 정렬합니다. 데이터가 빠진 상성은 0으로 가정하지 않습니다.

`31인으로 펼치기`에서 같은 상위7인 아래 증조8명·고조16명을 펼칩니다. 접기·확대·패닝은 입력을 바꾸지 않습니다. 넓은 트리는 내부에서 이동하며 노드 찾기로 깊은 인자도 편집합니다. `31인 인자 계획·배분 설정`은 현재 선택한 목표 인자의 생성 적성과 혈통 고정을 반영합니다. 옛 V1의 로테이션·유전자 설정은 보존만 하고 배분·계획 비교에 사용하지 않습니다. **7인 배치안 보기**와 **31인 적인자 배분안 만들기**는 독립 기능이며, 각각 전후 차이를 확인한 뒤 명시적으로 적용하거나 취소합니다. 같은 캐릭터 본체의 직접 부모/자식 및 부모 두 자리 중복은 금지하고, 서로 다른 가지의 재사용은 허용합니다. 잘못된 기존 계획은 삭제하지 않고 수정 경고를 표시합니다.

**스킬·서포트 분석 → 인자작 계획**에서 부모·조부 등 소유 노드를 선택해 실제 보유(사용자 기록)·제작 목표와 별수를 입력합니다. 기본 계보는 초상화·혈통·적인자·상성에 집중하며, 인자 편집기의 접힌 **인자 기록 관리**에서 기록 초기화와 조상 연결을 관리합니다. UUID는 내부 연결과 JSON에 보존합니다. 미입력·부분 입력·전체 목록 확인을 구분하며, 기록은 조부 재배치 시 같은 소유자를 따라가고 인물/의상 교체 시 제거됩니다. 잠금된 인자의 기록은 명시적으로 편집할 수 있습니다. 현재 자료에는 백인자 자격을 직접 인증하는 표가 없어 분류는 검토 필요로 유지합니다.

대회 스킬과 자기·직접 부모·조부·깊은 조상의 기록을 비교한 뒤 노드별 우선순위를 정하고 **선택한 인자의 서포트 추천**을 실행합니다. 기본은 현재 한국에서의 인자작이며 미래시는 별도 명시 모드입니다. 일반 P6 전역 목표와 노드 목표는 자동 합산하지 않습니다. 최종 본육성 덱은 원래 시간 기준의 수급 정보로 따로 비교하고 부모·조부의 인자작 덱으로 복사하지 않습니다. 실제 DB 통합 사례와 계산 경계는 [P7 검증 보고서](docs/P7_LINEAGE_SKILL_INTEGRATION_VALIDATION.md)를 따릅니다.

상단 **저장·복원·비교**에서 여러 계획을 수동 저장하고 이름 변경·복제·삭제합니다. 새로고침 후 마지막 저장 계획을 미리 보고 검증된 계획을 함께 복원하면 계보·인자·설정을 한 번에 적용합니다. 저장소 오류가 나도 JSON 파일로 현재 입력을 백업할 수 있습니다. JSON 가져오기는 현재 게임 ID와 계보 무결성을 검사한 뒤 명시적으로 적용하며 파일을 외부 서버로 보내지 않습니다.

같은 캐릭터·의상도 각 인자에 별도 UUID를 부여합니다. 백인자 편집은 UUID를 유지하며 **인자 기록 새로 시작**은 새 UUID로 바꾸고 선택 인자의 기록·목표·적인자를 비웁니다. 조상 자료는 남겨 재확인을 요구하며 잠금된 혈통은 먼저 해제해야 합니다. 계획 복제는 같은 실물의 사본이므로 인자 UUID를 유지합니다.

스킬 우선순위의 **빠른 선택 목록 편집**에서 자주 쓰는 스킬을 이름으로 검색해 추가하고 삭제·정렬할 수 있습니다. 새 환경의 목록은 비어 있고 기존 사용자 목록은 보존합니다. 목록과 테마는 계획 V1과 별도의 브라우저 환경설정입니다. 목록에서 지워도 이미 지정한 목표는 남고, 실제 목표는 최대10개입니다. 캐릭터·카드·백인자·스킬 검색에는 이름과 별칭을 사용하며 DB ID는 검색되지 않습니다.

계획 두 개의 계보와 백인자·서포트를 비교할 때 현재 데이터로 다시 계산합니다. 저장 당시 점수는 참고값이며 서로 다른 조건의 점수로 우열을 판정하지 않습니다. **7인 계보 PNG / 31인 전체 계보 PNG**는 실제 초상화·이름·의상·적인자의 트리로, **현재 서포트 6장 PNG**는3×2 편성과 전체 양립 목표의 수급표로 출력합니다. 기본 PNG에 개발용ID·UUID·장문 출처를 인쇄하지 않으며, 내부 대조 자료는V1 JSON·감사 데이터에 보존합니다. 이미지 실패 시 같은 대상의 이름·인자·계산을 남깁니다. 저장 계약은 [P8 보고서](docs/P8_PERSISTENCE_EXPORT_VALIDATION.md), 현행 UI·실제 화면·출력·회귀는 [P8.6 보고서](docs/P86_INTEGRATED_UX_OUTPUT_VALIDATION.md)를 따릅니다. [P8.5 보고서](docs/P85_UI_ASSET_INTEGRATION_VALIDATION.md)는 이미지 통합의 이전 이력입니다.

로컬 이미지 매핑은 **의상272종·서포트566장 전부**, 썸네일과 카드 아트 총1,404PNG입니다. 카드 목록에서 타입·레어도·카드명·한국 출시 필터를 함께 적용할 수 있습니다. 대회는 대표 시나리오·형식·거리·경기장으로 짧게 표시하며 예정14개를 기본으로 보여 줍니다. **지난 대회 목록 포함**으로 나머지39개를 열 수 있고 저장 계획의 과거 대회 선택도 유지합니다.

이미지 공개 재배포 허가는 확보하지 않았으며 **838개 ID 모두 pending**입니다. 출처·원본 ID·파일별 근거는 [이미지 출처 문서](docs/P85_ASSET_SOURCES.md)와 `data/assets/p85-manifest.json`에 있습니다. 개발용 파일은 `data/local/p85-assets/game-assets/`에 분리하고 일반 공개 빌드에는 포함하지 않습니다. 전체 게임 자료의 프로덕션 공급·호스팅 및 승인 자산의 공개 검토는 P9 범위입니다.

상단 `데이터 기준 확인` 또는 `http://127.0.0.1:5173/?view=data`에서 P0 출시 필터 검증 화면을 볼 수 있습니다. 화면 사이를 이동해도 현재 입력한 계보는 유지됩니다. 새로고침 전에는 실제 자료 화면의 계획을 수동 저장하거나 JSON으로 백업하세요. 가상 fixture 진단 화면은 실제 계획 저장 대상과 별개입니다.

현재 로컬 변환본은 인물 135명·의상 272개입니다. 한국 출시 미확인은 별도 옵션으로 포함하며 미출시와 구별합니다. `?view=fixture`에서 기존 가상 예시·회귀 화면을 열 수 있습니다. 로컬 원자료는 정적 배포에 자동 포함하지 않습니다.

상단 `스킬·서포트 분석` 또는 `/?view=skills`에서 P3/P4를 엽니다. 대회·각질·인자작 시나리오·성향을 선택하고 본육성 서포트 6장과 돌파를 설정합니다. 실제 2,223스킬·566카드의 조건·효과·Pt를 연결하며, 녹딱 우대 이유와 일반 힌트·이벤트·금색 하위 수급을 표시합니다. 한국 스킬 출시 미확인 연구 목록과 가용 카드 분석을 구분하고, 마신·발동률 근거가 없으면 정성 등급을 사용합니다.

```powershell
npm.cmd run data:import:p3
```

**인자작 서포트 6장 추천**에서 계산하면 이벤트 분기가 양립하는 목표·녹딱·중복을 비교한 6장과 교체/대체안을 표시합니다. 모든 잠재 경로와 미확인 이벤트는 별도 목록으로 보존하며 성공·획득 보장을 뜻하지 않습니다. 조건별 정성 가치를 주목적으로 두고 같은 가치에서 우선 녹딱과 공략 참고를 비교합니다. 보유 카드·돌파 등록과 대여1장 제한은 선택 사항이며, 기본은 전체 가용 카드의 가상 설계입니다. 계산은 Worker에서 수행하고 조건이 바뀐 결과는 숨깁니다. 범위를 제한한 탐색은 전역 최적으로 표시하지 않습니다.

**전역 핵심 스킬·우선순위**에서 일반 백인자 목표를 최대 5개 검색·선택합니다. 우선 확보(+8)·강력 우대(+24)는 기존 정성 점수와 분리한 사용자 정책값이며, 필수 확보는 같은 6장·양립 가능한 이벤트 계획에서 수급 기회를 요구합니다. 기본·맞춤 편성과 얻고 잃는 스킬, 녹딱·공략 주요 목표 손실을 비교합니다. 설정 변경은 자동 재계산하며 대회·각질을 바꿔도 선택은 유지합니다. `기본 추천으로 돌아가기`는 선택을 초기화합니다. 실제 백인자 생성·계승 성공을 보장하지 않습니다. 실제 DB 32사례와 정책 민감도·검증 한계는 [P6 검증 보고서](docs/P6_USER_SKILL_PRIORITY_VALIDATION.md)를 따릅니다.

[P6.1 탐색 감사](docs/P61_SEARCH_OPTIMALITY_AUDIT.md)에서 기존 P4.1 편성과 P6 복수 지정 편성을 동일 조건으로 비교했습니다. 두 편성은 모두374+8=382점이고, 현행 균형 동률 기준에서는 공급 중복이 적은 P6 편성이 우위입니다. 합집합11장462조합 전수와 다른 실제 대회2건의 확대 탐색을 확인했으며 엔진·정책은 유지했습니다. 전체DB 전역 최적성 인증은 아닙니다.

**P5 미래시 대회**는 2026-11-05～2027-11-04의 챔미·LoH 후보14건입니다. 기존5건을 재사용하고 신규9건을 추가해 전체 대회53건을 선택합니다. 2027년7～11월은 정확한 시작일을 만들지 않고 예상 월로 표시하며 11월LoH는 기간 경계 후보입니다. 미래시 가용성은 **일본 출시일↔대응 일본 대회일**로 비교하고 한국 예상일은 표시용으로 구분합니다. 미래시를 끄면 현재 한국 출시 근거로 제한합니다. 가까운/중간/먼 대회는 검증 설명 수준을 달리하며 기간으로 스킬을 감점하지 않습니다.

P5 추천은 공략 목록의 절대 우선을 제거하고 **양립 가능한 정성 가치 합계 → 동률 녹딱·공략 참고·편성 구성**으로 비교합니다. 정성 가중치16/10/8/6/2는 유지했습니다. 직전 출시 후보는 기본 반영·일반 교체·보류로 구분하며 추가 이득과 큰 인자 재제작 부담의 확인 근거가 없으면 별도 추천을 만들지 않습니다.

준비된 전달 ZIP을 로컬에 보존한 뒤 별도 팩을 만들려면 `npm.cmd run data:import:p5`를 실행합니다. 현재 P3/P1/SQLite의 provenance 해시를 먼저 확인하며 기존 팩은 변경하지 않습니다. 최신 사용법·14대회 추천·충돌16건·검증과 잔여 공백은 [P5 통합 보고서](docs/P5_INTEGRATION_VALIDATION.md)를 따릅니다. 이전 [P4.1 보고서](docs/P41_RECOMMENDATION_QUALITY.md)는 변경 전 정책의 이력입니다.

명칭·이벤트 자료는 [트레이너스 교차검증](docs/P3_TRAINERS_CROSSCHECK.md), 미래 대회·출시 순서는 [P5 보고서](docs/P5_INTEGRATION_VALIDATION.md), 현행 기본·맞춤 추천 비교와 검증 경계는 [P6 보고서](docs/P6_USER_SKILL_PRIORITY_VALIDATION.md)를 따릅니다. 기존 P3 팩은 2,223스킬·566카드·16,207경로·5,457이벤트입니다. 서포트 출시는 2차 자료469장·미래시97장이고, 기존 대회는 챔미43개·공식 LoH1건이며 P5 후보를 별도 연결합니다. U-tools 1,993행은 참고용이며 한국 추천 정량 인증·적용은 0건입니다. 초기 P3/P4/P4.1 보고서는 이전 상태의 이력입니다. 종마 추천은 추가하지 않았습니다.

`check`는 ESLint, TypeScript, P0/P1 및 P3 실제 부분 집합 계약 검증, P0～P8.6 단위 테스트, 정적 빌드를 실행합니다. `build`의 사전 단계에서도 데이터 검증에 실패하면 빌드를 중단합니다. 전체 실제 자료가 없어도 기존 회귀와 작은 실제 부분 집합으로 검사할 수 있습니다. 별도 교차검증·P4.1～P8 비교·전체 실DB 브라우저 검사는 준비된 로컬 팩·정규화 자료·기준선이 필요합니다. `data:validate:p5`는 출시순서·정책비교·14대회추천·직전출시·SQLite 검사를, `data:validate:p6`는 기존 P5 회귀·우선순위·필수 수급·미래시·보유/대여·후보 확장·민감도 32사례와 SQLite 검사를 실행합니다. `data:validate:p61`은 두 편성의 동일 조건·11장 전수·타 대회 표본을, `data:validate:p7`은 부모·조부·최종3종과 소유/세대·노드 범위·현재/미래·보유대여를, `data:validate:p8`은 실제 ID의 7/31인 입력 일치·159점·12/6성·6배치·저장 6장 재평가·저장 실패·원본 무결성을 검사합니다. `data:validate:p85`는 전체 이미지·63종 필터 조합·53대회 표시·원본 무결성을 검사합니다.

비공개 이미지 캐시를 다시 대조하거나 정적 경로를 검증하려면 다음을 실행합니다. `build:private-assets`는 공개용이 아닌 `.preview/p85-private-static`에만 출력합니다. 일반 `build`와 P9 공개 배포에 이 디렉터리를 복사하지 마세요.

`data:validate:p86`는 작업 전에 보존한 `.preview/p86-baseline`과 현재 엔진·도메인·원본 팩 및 이전 산출물의 바이트를 대조하는 이번 변경 감사입니다. 일반 실행·빌드는 이 로컬 기준선에 의존하지 않습니다. `data:validate:p86:static`은 기존 권리 경계를 그대로 검사하면서 이번 로그와 캡처를 별도 보존합니다.

npm.cmd run data:validate:p86:static

npm.cmd run data:assets:p85:public-audit
